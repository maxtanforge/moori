# Linux 部署验收

使用可重新初始化的 Linux Docker 测试环境。准备一台运行主服务的机器和一台远程节点，分别使用新的控制数据库和 Agent 账本。记录源码提交、镜像摘要、部署 ID、关键日志和 Docker 现场状态。

## 基础部署

1. 使用 `make build` 构建两个程序。需要验证镜像时，按[发布指南](release.md)构建两个镜像，并用 `docker compose -f deploy/compose.example.yml config` 和 `docker compose -f deploy/compose.agent.example.yml config` 检查部署配置。后一条命令需要先设置 `MOORI_ENDPOINT`。
2. 按[部署指南](deployment.md)启动主服务，通过主服务 HTTP 地址直连初始化管理员，退出后重新登录。配置可选网关时，同样验证初始化或登录，并确认可信网关覆盖 `X-Forwarded-Proto`、保留原始 `Host` 及 WebSocket Upgrade。检查 `GET /healthz` 和持久化的 `moori.db`。
3. 启用 local，无需另起 Agent。创建测试项目和目标，部署只含一个长运行容器且固定镜像摘要的 Compose 版本。确认控制台显示 `succeeded`，并与本机 `docker compose ls` 和容器状态核对。
4. 通过控制台或 CLI 签发远程 Agent 凭证，验证远程节点能通过主服务的 WS 地址主动连接并使用 `agent.db` 持久化。使用 Traefik 的环境可再验证 WSS 入口。创建远程部署目标，重复同一部署验证。重启主服务和 Agent，确认已有容器、镜像、网络和卷仍可发现，Docker 和主机信息会重新采集。
5. 使用[目标范围内的 CI 凭证](integrations.md)，对同一目标使用同一个 `Idempotency-Key` 提交两次。两次返回同一个部署 ID，Docker 上只运行预期的 Compose 项目。核对请求提交后直接入队，并验证摘要不匹配和越权请求被拒绝。
6. 发布第二个版本，然后[回滚](deployment-maintenance.md#回滚部署)至第一个成功版本。记录 `rollback_of`，核对实际镜像摘要和命名卷数据。

## Docker 管理与接入

| 操作 | 核对结果 |
| --- | --- |
| [共享 Registry](docker-management.md#registry) | 在系统设置登记一次私有仓库，分别从本机和远程 Agent 验证与拉取。验证、拉取和部署均由对应节点完成。通过实际网关验证远程凭证发放，再核对轮换及停用后的行为。 |
| [Compose 模板](docker-management.md#compose-模板) | 保存模板并增加版本，为两个节点选择各自测试卷和自建 Bridge 网络。核对预览、部署状态和 Docker 实际挂载。在绑定外部资源的部署等待派发时尝试改绑目标，确认原选择仍受到保护。用不符合驱动要求的资源确认部署会在执行节点拒绝。 |
| [Compose 同机切换](docker-management.md#compose-模板) | 在单文件项目里使用没有显式 `name` 的外部卷和网络，以及已发布的固定端口。核对评估页名称、端口占用提示和返回源文件；保存后选择原节点的目标，先用临时端口试部署。再模拟正式切换失败，确认保留的旧容器可重启，数据仍可读取。如果服务共用可写卷，安排停机切换。 |
| [容器、卷和网络](docker-management.md#容器卷和网络) | 查看容器详情和尾部日志，执行重启、创建卷和网络、连接与断开独立容器。核对节点结果、卷引用和 Docker 现场。分别在本机 Docker 和远程 Agent 的运行容器上从列表或详情进入终端（远程 Agent 需 WSS），在容器内执行交互命令并调整面板尺寸。退出后核对退出码与开始、结束审计，再用「重新连接」进入。确认非管理员和已停止容器无入口，第 9 个并发会话被拒绝。 |
| 节点显示名和权限 | 平台管理员为本机和远程 Agent 设置名称。检查切换器、目录和概览同步，重启主服务后名称保留。用项目管理员登录验证改名被拒绝，再清空名称验证恢复默认。核对系统主机名和平台审计。 |
| [独立容器维护](docker-management.md#维护-compose-配置和重新部署) | 用一次性测试容器验证端口、环境变量和重启策略变更。分别核对匿名卷名称、命名卷子目录和数据在替换前后的对应关系，再验证尊重容器停止时限、慢速健康检查和启动失败时的恢复。 |
| [Compose 维护](design.md#节点维护模型) | 修改受管项目后核对配置和部署记录，再重新部署并检查服务重建。提供受支持的外部项目定义，确认文件读完后才可预览。核对原项目名及文件未列出的服务仍在。模拟读取受管配置失败，核对同页重试后能加载。对受支持的外部单文件项目执行「评估纳管」，核对逐条转换说明、镜像按节点快照摘要固定，部署后核对已有卷和网络回绑原名且数据保留，确认正常后删除原项目完成纳管；再以不受支持的项目确认拒绝。 |
| [节点监控](observability.md) | 检查主机与容器历史的样本和时间轴，核对部署、回滚、重启标记。停留在该节点页并停止测试 Agent 超过 90 秒，再启动，核对状态无需跳页即可更新，当前列表筛选仍然有效。配置测试 Webhook 后验证两次转换及重复投递去重。 |
| Docker 事件与资源刷新 | 分别在本机和远程测试节点批量启停容器，并从宿主机执行测试项目的 `docker compose up -d` 和 `docker compose down`。对照 Docker 完成时间、资源接口的 `section_times.containers` 和页面显示时间。断开再恢复节点连接后，在没有后续 Docker 操作的情况下核对项目列表。连续刷新同一资源页时，在浏览器网络面板核对未变化时的 `304` 和下一次变更后的 `200`。 |
| [Gitea 发布事件](integrations.md#gitea-发布-webhook) | 为已存在的 Moori 发布版本发送带签名的 Gitea 发布事件，并重投同一事件。确认两次指向同一部署，且请求通过目标权限校验后进入队列。 |
| [Gitea Actions 直接部署独立容器](integrations.md#gitea-actions-直接部署独立容器) | 在控制台给本机 Docker 与远程 Agent 各建一个测试目标，可分别归属不同项目。签发一枚令牌并授权两者；Runner 只使用一个 `MOORI_TOKEN`，以同一幂等键分别提交两个目标。核对各自的操作 ID、状态和 Docker 镜像摘要。同一目标重投须返回原操作，未授权目标须拒绝。撤销令牌后再次提交，两个目标都须拒绝。 |
| [独立容器更新 Webhook](integrations.md#独立容器更新-webhook) | 在 local 和远程 Agent 绑定测试容器，用 Runner 提交两个不同摘要并回退到第一个。核对 Docker 容器名、挂载数据和镜像摘要。重复提交相同幂等键应返回同一操作，换摘要应返回冲突。确认越界镜像、其他绑定的凭证和已撤销凭证均被拒绝。 |

## 断线、权限与恢复

| 测试操作 | 核对结果 |
| --- | --- |
| 部署运行时断开 Agent 与主服务的连接，保持 Docker 可用 | 本机执行继续。重连后，同一执行回报结果。 |
| 重启 Agent，账本存在已受理但尚未启动的任务 | 任务可沿用原执行 ID 继续。 |
| 停止正在执行的 Agent，再重启 | 如果没有保存终态，执行进入核查并保留目标锁。同一任务不应重新启动。 |
| 让测试容器在 Compose 健康等待完成前退出 | 执行不能报告成功。若 Docker 可能已接收变更，检查核查状态及锁。 |
| 用测试账户连续输错密码 5 次，重启主服务 | 正确密码在锁定期内仍不能建立会话，审计包含锁定事件，期满可重新登录。 |
| 用提交凭证和另一张同目标凭证分别查询部署日志 | 提交凭证可读取已有的 CLI 尾部，另一张凭证不可读取。 |
| 撤销或使 Agent 凭证过期 | 现有连接的后续请求与同一凭证重连均被拒绝。检查已经运行的 Docker 操作。 |
| 在排队部署派发前撤销其 CI token | 该工作不得启动。 |
| 对尚未派发的任务重复请求取消 | 产生一个取消结果，Compose 不会启动。 |
| Compose 应用变更时请求取消 | 核对 CLI 是否停止。Docker 结果未知时保留目标锁并进入核查，已确认的成功保持不变。 |
| 部署测试文件密钥，再轮换和撤销其版本 | 授权服务能读取文件，其他服务不能。原执行保留原版本，引用已撤销版本的新回滚被拒绝。 |
| 按[备份恢复](backup-recovery.md)启动备份库 | 旧 Agent 凭证失效。首次凭证重发保留原代次，原账本参与盘点。逐目标释放后核对已有目标可以部署。全部历史目标释放后，再验证新目标接入、Registry 凭证配置与节点 Docker 操作。 |

每次演练后将 Moori 状态与 Docker 现场交叉核对。选一个处于核查中的目标，确认其他测试目标可以继续部署。先确认现场安全，再释放核查目标。

按[部署运维](deployment-maintenance.md)额外验证三项：隔离声明和过期条件未满足时不能放弃任务，停止容器正在引用的密钥文件也会被清理命令保留，主服务日志目录恢复可写后 Agent 能重传保留的输出。
