# 节点监控

主服务在独立 SQLite 中保存采样历史、活动告警和告警记录，默认文件为数据目录下的 `moori.db.metrics`，可通过 `serve -metrics-db` 更改。Docker 管理所需的节点联系状态和最新资源快照另存于 `moori.db.resources`。两者都不包含在主数据库备份中。

从[运行实例的数据目录](deployment.md#数据目录)执行本页的主服务 CLI 命令。

```bash
moori agent-health -agent host-01
```

有项目读取权限的用户也可通过会话接口 `GET /api/v1/projects/{project}/targets/{target}/health` 查看。

## 联系与采样

认证通信正常时，主服务约每 15 秒刷新联系状态。local 和远程 Agent 约每 30 秒上报 Linux CPU、可见内存和节点数据目录所在文件系统的容量。执行通信优先于诊断。

健康样本以主服务接收时间记录，CPU 使用率需有前一次计数。历史曲线来自资源快照中的节点或 Docker 采样时间，清单刷新可携带最近一次完整采集的指标，主服务按实际测量时间去重。早于该次完整采集的旧指标会被跳过。主服务也会跳过晚于接收时间超过 150 秒、或早于接收时间超过 90 秒的采样。主服务和节点应同步时钟。节点代次变更后，控制台读取新代次的历史。

## 状态与活动事件

- 当前代次从未连接时状态为 `never_seen`。超过 90 秒没有新联系时状态为 `offline`，并产生 `agent_offline` 告警。
- 运行环境的侧栏与节点页随资源请求刷新连接状态，连接状态按联系时间判断，快照是否过期另行提示。
- 缺失或过期样本不产生当前资源健康结论。
- 联系和采样都有效时，文件系统可用空间不超过 10% 显示 `disk_low`。
- 主服务约每 15 秒评估节点并持久化活动事件及开始时间。恢复联系解除离线事件；新的有效样本可用空间达到 15% 才解除磁盘事件，缺失或过期数据不解除事件。

`alerts` 表示查询时计算的情况，`incidents` 表示持久化活动状态。CPU 和内存默认在使用率连续两分钟达到 90% 时触发，恢复阈值比触发阈值低 5 个百分点。缺失或过期的采样不能触发使用率告警或认定为恢复。

## 历史与事件

平台管理员在本机或远程节点的「节点概览」打开「查看监控」，查看主机 CPU、内存、文件系统容量和非回环网卡的合计收发速率。在容器列表或详情打开该容器的监控页，可查看 CPU、内存、网络和块设备 I/O。

网络速率按相邻采样之间的字节增量和实际间隔计算，图表以 B/s、KiB/s、MiB/s 等单位显示，最多保留两位小数。低于 0.01 B/s 的非零流量、零流量和无采样分别显示为 `<0.01 B/s`、`0 B/s` 和 `—`。

监控可选择最近 1 小时、6 小时、24 小时或 7 天。页面默认每 30 秒自动刷新，可暂停或手动刷新，离开监控页时停止轮询。刷新保留选择的对象和时间范围。最近采样及图表读数使用实际采样时间。图表时间轴、图例和读数按浏览器时区显示为 24 小时制，数据中断会在图上留下间隔。图表可拖拽缩放并双击复位，缩放窗口在自动刷新后保留，切换对象或时间范围后复位。节点时间轴显示查询范围内最近 100 条部署、回滚和已确认的重启事件，节点告警单独列出。

每条时间序列在每个 30 秒时间桶最多保留一个点，每个节点代次最多跟踪 64 个容器。每小时清理后，全库保留最近 7 天内最新的 200 万个采样点。查询按时间范围取各时间桶内的最新样本。

## 通知

平台管理员在「系统设置 → 告警通知」管理告警阈值与通知目标，保存后无需重启主服务即可生效（评估循环每个周期重新读取策略）。默认 CPU 与内存阈值为 90%、持续 2 分钟，恢复阈值比触发阈值低 5 个百分点。

通知目标为 HTTP(S) Webhook 地址，最多 10 个，投递时不允许携带凭据或片段。每个告警触发和恢复事件会向配置的目标 JSON POST `id`、`agent`、`generation`、`code`、`state` 和 `at`。触发和恢复分别使用 `fired` 与 `recovered`。同一事件共用相同的 `Idempotency-Key`；触发和恢复在各接收端各自按顺序投递，失败只重试该接收端。非 2xx 响应和请求失败最多尝试 8 次，超过 24 小时停止投递。只为存在通知目标期间发生的变化排队，发送前会跳过失效的节点代次和已移除的目标。告警历史始终记录，审计页记录策略与目标的变更。

环境变量仅作为升级前的初始值：`MOORI_ALERT_WEBHOOK` 会在通知目标为空时导入一次（之后以控制台为准，删除环境变量即可），`MOORI_ALERT_CPU_PERCENT`、`MOORI_ALERT_MEMORY_PERCENT`、`MOORI_ALERT_SUSTAINED_FOR` 在控制台未自定义时作为默认阈值生效，例如 `95`、`92`、`3m`。主服务启用监控时会先校验告警配置，再启动 local 执行器。

## 最新资源快照与采集开关

平台管理员在「运行环境」查看 local 和远程 Agent 的最新资源快照。本机和远程 Agent 监听 Docker 资源事件。宿主机执行 `docker compose up` 或 `down` 时，节点在约 2 秒内合并一批事件，再读取容器和项目清单。事件流重连后，即使 Docker 没有产生新事件，节点也会重新核对清单，补上断线期间的变更。事件和管理操作触发的刷新优先读取资源列表。逐容器配置、资源统计和主机采样按约 30 秒的完整采集周期更新。磁盘用量最多复用约 5 分钟，采集时间沿用实际读取时刻。

前台资源页约每 5 秒核对快照；数据未变化时，条件请求可省去重复传输。操作记录的完成时间、Docker 各类资源的最后采集时间、主服务的接收时间分别记录。CPU 使用率需要连续采样，容器网络与块设备 I/O 显示累计值。Agent 可用 `-inventory=false` 关闭资源快照和历史曲线采样。

Agent 设置 `-host-metrics=false` 停止上报独立健康样本，启用盘点时仍可上报资源快照和历史样本。主服务设置该参数会禁用历史采样和告警评估，节点资源列表和 Docker 管理继续工作。容器化节点的采样可见范围受挂载与命名空间影响，实机验收时应与宿主数据核对。
