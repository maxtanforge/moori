# Docker 资源管理

平台管理员从「运行环境」的环境目录进入本机 Docker 或远程 Agent。目录可以按节点名称或标识搜索，并按连接状态筛选。左侧显示当前节点和连接状态，存在多个节点时可直接切换。节点概览、容器、Compose、镜像、网络、卷和主机入口在所选节点下面。容器列表可按名称、镜像或 Compose 项目搜索并筛选状态，标题旁显示总数或筛选后的命中数。后台更新保留当前筛选和详情，读取失败时继续显示上次快照并提示。发现、镜像拉取和资源操作均指向所选节点的 Docker。主服务保存共享配置、授权和操作记录，Compose 在节点上执行部署。操作记录每页显示 20 条，可翻看当前账号在所选节点最近 30 天的变更。

本机空闲时，容器启停、重启、暂停、恢复及配置读取等短操作由主服务直接调用 Docker，并在提交响应中返回结果。已有操作或部署需先执行时，短操作进入后台队列。远程 Agent 的操作仍通过队列派发。返回容器列表时保留当前搜索、筛选和滚动位置，焦点回到原容器。

平台管理员可以在节点概览编辑显示名，留空后恢复默认名称。显示名由主服务保存，节点概览同时展示采集到的系统主机名。修改记录可在[平台审计](access.md#审计)查询。

## 资源限制与卷容量

独立容器创建或编辑时，在「资源限制」中设置 CPU 核数、内存上限和 PID 上限，留空或填 0 表示不限。编辑时回显 Docker 当前配置。只改资源且 可拖动滑块或输入精确数值，滑到最左端表示不限。Docker 支持原地更新时，保留容器 ID 与可写层。清除 CPU 或内存上限、转换旧式 CPU quota，或同时修改需要重建的配置时，预览会标明重建。已有内存与交换空间总上限时，新的内存上限须在其范围内。清除内存上限时，会同时清除有限的内存与交换空间总上限。Compose 服务仍通过 Compose 配置维护。

创建卷时，可以选择本地持久卷或带容量上限的 tmpfs 临时内存卷。tmpfs 卸载后数据清空。卷页面分别显示已用空间和驱动报告的容量上限。普通本地持久卷共享底层文件系统的可用空间，页面不会为它保存一个无法执行的配额。

### 部署记录

在独立容器详情打开「部署记录」，可查看手动创建或重建、CI 和 Webhook 的记录。记录按节点、凭证代次和容器名称归集。同一次绑定下更换容器 ID 后，已记录容器名称的历史仍可查询。启停、暂停和删除可在节点的「操作记录」查看。

Moori 受管 Compose 的部署记录按目标查询。从 Compose 项目详情或所属服务容器详情进入，点记录 ID 可查看执行日志和可用的回滚操作。记录按最新优先排列，每页 20 条，支持前后翻页。

## Registry

每台节点经本机 Docker Engine 拉取镜像。在主服务登记一次仓库地址和凭证，本机和所有已接入的 Agent 共用。凭证由 Moori 的 Registry 配置提供，节点上的 `docker login` 配置不参与这条调用链。

平台管理员在「系统设置 → 镜像仓库」添加 Docker Hub（`docker.io`）或其他 Registry 的主机名，可带端口。可以限定仓库路径前缀。公开仓库可使用匿名访问，私有仓库优先使用只读访问令牌。

节点启动时采集已有镜像。Moori 执行资源变更后触发重新采集，外部变更由周期采集发现。「发现的镜像仓库」打开时读取所选节点快照，页面可见期间每 15 秒核对一次。已配置的仓库和凭证由管理员维护。

首次启动时，主服务会自动创建并加载加密主密钥。Docker 默认使用 `/data/moori.key`，请保留 `/data` 挂载并单独备份密钥。已有加密数据却找不到配套密钥时，主服务不会生成新密钥；请恢复原文件并重启。详见[密钥管理](secrets.md)。

1. 按[部署密钥指南](secrets.md)配置主服务的加密密钥，然后保存私有仓库凭证。仓库详情页可以轮换凭证或停用仓库。
2. 同一域名有多个配置时，系统优先使用与镜像路径匹配的最长仓库前缀。同级匹配有多个时，需要明确选择仓库。
3. 在仓库选择「验证或拉取」，选择执行节点并输入镜像引用。验证在该节点检查仓库连通性和凭证。拉取将镜像保存到该节点的 Docker。
4. 部署时，节点根据发布快照中的镜像摘要拉取镜像。凭证轮换影响后续拉取，历史发布和回滚仍使用记录的镜像摘要。停用仓库后，执行节点无法再领取该仓库的凭证。

Agent 可直接通过 WS 连接主服务。需要从 Moori 领取私有仓库凭证的远程 Agent 使用 WSS 入口，凭证按次发放。网关终止加密连接时，主服务通过 `MOORI_TRUSTED_PROXY_CIDRS` 配置实际直连网关的地址，多个网段用逗号分隔。网关需覆盖客户端发送的 `X-Forwarded-Proto`，后端端口仅允许可信入口访问。local 通过进程内调用领取凭证。

## 容器、卷和网络

- 在节点的容器列表顶部选择「创建容器」，填写名称并选择镜像来源，输入该仓库下的镜像路径、标签或摘要。Moori 使用节点已有的镜像，缺少镜像时自动使用匹配的共享仓库凭证拉取。没有匹配配置的公开镜像支持匿名拉取。预览确认后，Moori 在当前节点创建并启动独立容器。
- 桌面浏览时，从部署表单右侧分组导航下方进入预览；窄屏时使用表单底部的按钮。
- 容器详情标题旁可刷新当前信息。操作区显示适用的运行和部署操作。流水线、Webhook 和删除入口位于「更多操作」。
- 容器详情通过「概要」「运行配置」「环境与标签」查看状态、配置和键值信息。离开「环境与标签」时取消读取并清除当前值。单个容器启停、重启、暂停或恢复后，在发起位置更新状态。从列表直接进入日志或监控时，页面内返回入口回到原列表。从详情进入时，返回原详情分区。批量启停只处理当前列表中已勾选且状态符合的容器，确认前显示目标名称，提交后逐项显示执行结果，并按 Docker 已确认的状态更新列表。关闭窗口后可以从操作记录继续查看。
- 从列表或详情可删除已停止的独立容器。删除需要二次确认，默认保留挂载卷。勾选「同时删除挂载卷」才会删除卷中数据。宿主机绑定目录始终保留，Docker 会拒绝删除仍有容器引用的卷。
- 在外部 Compose 项目详情选择「删除项目」，确认后停止并删除该节点上带有对应项目标签的容器。无需挂载 YAML，卷、网络、源文件和镜像均保留。需要清理网络时，到节点的「网络」页面单独确认删除。从已授权源文件页面删除时，卷选项默认不勾选；勾选后仅清理属于该项目且未被其他容器引用的本机挂载卷，外部卷保留。删除途中失败时需刷新核对剩余资源。Moori 受管项目继续通过对应部署维护。
- 日志默认实时跟随，可选择最近 100、200、500 或 1000 行，默认 200 行。暂停会冻结当前输出，手动刷新读取一次快照。恢复实时会重新读取选定尾部，再追加新日志。流连接不可用时，页面明确提示并约每 3 秒读取快照。页面隐藏或离开时取消当前读取。日志窗口按所选行数保留最近内容，单页上限为 64 KiB。滚到末尾时随输出更新，向上查看时保留滚动位置。
- 容器日志默认显示该容器最近一次启动后的输出，停止后仍可查看该次运行的日志。切换「全部运行」可查看同一容器 ID 仍保留的较早日志；重新创建的容器有新的 ID，不会混入旧容器的日志。本机直接跟随 Docker 日志，远程 Agent 需同步升级以支持按启动时间过滤；WSS 可中继实时日志，WS 则按快照刷新。
- 本机 Docker 或远程 Agent 节点上运行中的容器可从列表或详情选择「进入终端」。终端直接连接容器内交互 shell（bash 优先，无 bash 时回退 sh，TERM=xterm），按键与输出逐帧透传，面板尺寸变化即同步调整容器 TTY；进程退出时显示退出码，可用「重新连接」再次进入。点击「退出终端」会断开连接并返回原页面。终端仅对平台管理员开放，每次会话的开始与结束写入平台审计。本机由主服务直连 Docker，远程终端由 Agent 经 WSS 转发。主服务同时最多允许 8 个终端会话。
- 从容器详情可以跳到镜像、Compose 项目、挂载卷和已接入网络。资源详情列出同一节点快照中的关联容器，包含快照里的已停止容器。可从 Compose 项目详情进入配置维护。
- 镜像列表顶部可拉取镜像或导入 Docker 镜像档案。在「系统设置 → 镜像仓库」中可指定仓库和执行节点来验证或拉取。镜像详情可导出档案，也可以从每条已有标签旁的图标发起推送。
- 单独拉取镜像时，控制台显示排队或执行状态和等待时间。关闭弹窗后可从节点的「操作记录」继续查看。单次执行最长 6 小时，Docker 连续 15 分钟没有返回进度时结束等待。若记录显示「结果未确认」，可先查看节点镜像列表，再从操作详情选择「重新拉取」。成功后节点会重新采集镜像列表。
- 镜像列表标明「使用中」「未使用」或「使用状态未知」。已停止的容器也计入引用。可在列表或详情中删除未使用的镜像，目标节点会重新检查引用后请求 Docker 删除。删除成功后，列表和节点概览的镜像数会同步更新。
- 在镜像详情的「添加镜像标签」中选择镜像源，输入 `路径:标签`。添加只修改当前节点上的标签，原有标签保留；目标标签若已指向其他镜像，页面会提示更换。需要推送时，点击该标签旁的图标，选定匹配的共享仓库并确认。
- 导出由浏览器下载 `.tar`。导入会在所选节点执行 Docker 加载并应用档案中的标签，同名标签可能被替换。页面显示上传进度，上传中可取消，传输上限为 8 GiB。使用远程 Agent 传输档案时，浏览器需通过可信 HTTPS 网关访问控制台，Agent 通过 WSS 连接。网关的请求体上限和超时需覆盖实际传输。
- Docker 卷属于单个节点。可以创建命名卷、检查引用，或删除 Docker 确认未被使用的卷。
- Docker 网络属于单个节点。可以创建 Bridge 网络、检查连接，或接入和断开独立容器。Compose 服务的网络关系由其 Compose 配置维护。
- 从独立容器详情的「更多操作」选择「配置流水线」，绑定部署目标并签发 CI 令牌。CI 可直接提交新镜像摘要更新，提交旧摘要可回退镜像；也可以选用独立的 Webhook。Compose 服务通过对应项目的部署更新。[流水线接入](integrations.md#gitea-actions-直接部署独立容器)

## Compose 模板

平台管理员在「系统设置 → Compose 模板」粘贴或上传 Compose 文件，也可从已保存的部署记录提取模板。上传新内容会增加一个版本。模板可以声明可调整的端口、非敏感环境变量、外部卷及网络绑定。镜像使用固定摘要，应用密钥通过部署目标的密钥绑定提供。

选择模板版本和部署目标后，在「校验并预览」核对将要部署的配置。预览校验 Compose 内容、目标及密钥版本。有外部绑定时，提交内容还需匹配预览核对的节点和快照摘要。卷和网络的存在与驱动由执行节点在部署时检查，支持已有的 `local` 驱动命名卷（无驱动选项）和用户创建的本地 `bridge` 驱动网络。部署仍经过目标的权限校验和执行流程。平台管理员可以提交和回滚控制台模板生成的部署。

在两台节点复用同一模板时，分别从目标节点清单选择各自的卷和网络。提交、派发和回滚沿用外部资源快照绑定的节点和凭证代次。目标更换节点后，需要重新选择资源并提交。使用外部资源绑定时，主服务与远程 Agent 应使用同一版本。卷数据按应用的策略单独备份和恢复。


## 维护 Compose 配置和重新部署

编辑独立容器时，如果换了镜像而目标节点还没有该镜像，Moori 会先按镜像地址匹配共享仓库并拉取。拉取失败会保留原容器。若原容器已删除或重建，返回容器列表重新选择当前实例。

- 在节点的 Compose 详情打开「修改配置」或「重新部署」。Moori 管理的项目从当前成功版本读取镜像、端口、重启策略、卷、网络、标签和环境变量。修改时先比较配置，再提交新版本，提交确认期间锁定当前表单。服务的卷和网络从项目声明中选择，标签与环境变量按键值行维护。重新部署以当前成功版本的 Compose 内容重建服务。预览使用目标当前的密钥绑定。两种操作都绑定当前节点及代次，并生成新的部署记录。
- 外部 Compose 项目编辑页从节点授权目录读取原始文件。可按容器记录自动读取，也可显式登记路径。多文件按 Compose 读取顺序显示，逐份编辑、校验并预览，确认后可保存源文件或保存并部署。源文件被改动时，要重新读取后再提交。文件不可读时，页面展示当前运行配置，可返回项目详情删除项目容器。[授权与挂载方式](compose-support.md)
- 单文件的外部项目可在源文件页执行「评估纳管」。确认转换差异、卷和网络的实际名称以及固定宿主机端口后，保存为部署模板。从结果页进入部署时请选择原节点的目标，并核对预选的资源。可先用临时端口验证；正式切换时停止原项目并保留容器，确认新项目服务和数据正常后再清理。若切换失败，先释放新项目占用的端口，再恢复原项目。会写入同一数据卷的服务应避免同时运行。[转换规则](compose-support.md#纳管外部项目)
- 独立容器在容器详情打开「编辑配置」或「重新部署」。创建和编辑共用镜像、端口映射、重启策略、卷挂载、网络、标签及环境变量配置。按类型选择节点上的命名卷或输入 Bind 的宿主机绝对路径，并指定容器路径及读写权限。Bind 路径应由有权管理该宿主机的平台管理员设置。编辑页读取当前环境变量和标签的值，预览仅列出改动的键。表单自动识别改动，沿用未修改的配置和挂载选项。替换会重建容器可写层，启动或健康检查失败时尝试恢复原实例。应用前请核对停机影响和卷绑定。重新部署沿用 Docker 已分配的匿名卷。停止和健康检查所需时间超过实施预算时，Moori 会在停止旧容器前拒绝替换。
- 配置表单面向非敏感值。Moori 管理的 Compose 部署使用目标密钥绑定。静态网络地址、宿主网络、共享容器网络命名空间和自动删除等运行模式需要在节点上手动迁移。
